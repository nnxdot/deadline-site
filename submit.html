Submit a result

Run the public prompts against any model you can reach — your API key, your machine. Send in the raw replies and the maintainer grades them against the private tests. Verified, or it doesn't count.

Submit a Deadline 4.0 result

Download and extract the v4 task package and runner. It contains all 72 tasks, separate API and agent prompts, supplied projects, and public submission helpers. Hidden tests and solutions stay private.

Run python client.py --check-suite inside the extracted folder, then follow its API or agent instructions. Tokens and the exact suite must be recorded.

After the run, use python client.py --validate submission-v4.json and python client.py --package submission-v4.json. Open a v4 submission issue, attach the generated ZIP and paste its metadata. Keep dedicated receipts and agent transcripts for verification; do not include credentials or unrelated session history.

The maintainer grades submissions privately. Calibration continues; community results and certified runs have different verification requirements. The commands below this box are for the historical 3.x client.

01

Clone the repo

$ git clone https://github.com/violetweather/deadline-site
$ cd deadline-site

The prompts live in prompts/; the client script in client/. Python 3.9+, standard library only — nothing to install.

02

Run your model

Point the client at any provider. Your key stays on your machine. Easiest route: an OpenRouter key benchmarks any of hundreds of models with one flag — set OPENROUTER_API_KEY and pick a model id:

$ python client/deadline_client.py --openrouter --model qwen/qwen3-coder

Direct APIs work too: --type gemini, --type anthropic, or --type openai for any OpenAI-compatible endpoint (OpenAI, Groq, and local servers like Ollama with --base-url http://localhost:11434/v1 and no key). Set actual provider options with --params; --effort only labels the setting and does not change the request.

The script asks your model every task once — one blind attempt — and writes submission.json: the raw replies plus token counts.

Check the estimated cost before spending with --dry-run. Add --max-spend 10 to reserve against a $10 estimated budget and checkpoint before the next request would exceed it. This is a client estimate, not a provider billing limit.

The default remains v3.5. The local v3.6 preview uses --benchmark-version 3.6. Existing v3.5 answers can be carried with --extend old.json --out topup.json only when the full request prompt and provider settings match. A top-up extends one sample.

03

Package it

$ python client/deadline_client.py --validate submission.json

Validation checks completeness and metering without testing your answers or calling a model. Truncated replies stay incomplete; a fresh attempt belongs in a separate run.

$ python client/deadline_client.py --package submission.json

This writes submission.json.zip — real submissions run well past the ~65,000-character limit on issue bodies, and zipping code-heavy JSON shrinks it several times over — and prints a short issue body holding only metadata: model, effort, client version, task and token counts, and the sha256 of the JSON file inside the zip. No answers, ever.

04

Send it — attach, or open a PR

Attach the zip. Open the submission issue, drag submission.json.zip into it, and paste the printed body above the attachment. The hash in the body pins the file, so a swapped or edited attachment is detectable — and gets rejected.

Open the submission form

Or open a pull request. Add the file as submissions/<model>-<date>.json on a branch of your fork and open a PR, subject to GitHub's file-size limits. The commit is the receipt.

$ cp submission.json submissions/qwen3-coder-2026-09-08.json
$ git checkout -b submission/qwen3-coder
$ git add submissions/ && git commit -m "submission: qwen3-coder" && git push

Either lane is graded identically. Don't edit the file after generating it — the grader compares hashes, reply style and per-task receipts.

05

Get graded

The maintainer re-runs your replies against the private test suite in a sandbox and posts the verified score on your issue. It's then folded into your model's community average on the leaderboard — the site never shows individual submissions or usernames.

The rules
  • One blind attempt per task — no retrying until it passes.
  • No hand-written or hand-edited "replies". Obvious ones get rejected.
  • No peeking at tests — you can't, they're private. That's the point.

Submissions are graded in arrival order ✗ the deadline is midnight ✗ the deadline is always midnight
