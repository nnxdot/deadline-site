Implement this merge dialect exactly; familiar JSON merge-patch rules do
not override it. Input {initial: JSON value, layers: [{priority,enabled,patch}]}.
Sort layers by ascending integer priority, breaking ties by original array index.
Skip disabled layers. For each chosen layer merge its patch into the current root.
Return {document: final_value, applied: chosen_original_indices_in_execution_order}.

The recursive merge rules, in precedence order:
1. An object with EXACTLY one key '$delete' whose value is boolean true deletes
   the destination object member if present. At the document root deletion means
   null. Objects with extra keys are ordinary objects, not delete markers.
2. An object with EXACTLY one key '$replace' replaces the destination with a deep
   literal copy of its value. Do NOT interpret markers anywhere inside that copy.
3. Other objects recursively merge their members into the destination object;
   if the destination is not an object, start with an empty object. Existing
   unmentioned members remain. New object members apply the same recursive rules.
4. Arrays merge into the existing destination array (or start empty if it is not
   an array). Process incoming elements left-to-right:
   a. Exact {'$remove': string_id} removes ALL current dictionary elements whose
      'id' member equals that string. No match is a no-op.
   b. Otherwise a dictionary element with a STRING 'id' recursively merges into
      the FIRST current dictionary element with equal id, preserving its position.
      If none exists, recursively merge it into {} and append it. Later duplicate
      existing IDs are unchanged by an upsert.
   c. Every other element is literal data: append a deep copy only if no current
      element is structurally equal. Equality ignores object key order, preserves
      array order, and distinguishes booleans from integers (true != 1, false != 0).
      Nested markers in these literal non-ID elements are not interpreted.
5. All other values replace the destination, INCLUDING null, false, 0 and ''.

'$delete'/'$replace' wrappers are recognized only when recursively merging a
value, not by scanning literal data. '$remove' is special only as a direct incoming
array element. An object with '$delete':false is an ordinary object. Existing
arrays may contain duplicate IDs and values; only the stated operations remove
or deduplicate them. There is no input mutation visible in the returned protocol.

Bounds: JSON contains only null, booleans, strings, arrays, objects and integers
within signed 32-bit range; <=100 layers, <=10,000 nodes total, <=15 nesting
depth, <=1,000 elements in any input array, keys/strings ASCII <=100 characters.
Priority lies in [-1000,1000]. Groups contain <=34 inputs. Calls share no state.
The public examples deliberately show null preservation, typed array values,
quoted markers, first-ID upsert and removal of all duplicate IDs.

## Public examples

Input: {"initial":{"a":1,"list":[true,1]},"layers":[{"enabled":true,"patch":{"a":null,"list":[false,0,1],"quote":{"$replace":{"$delete":true}}},"priority":0}]}
Output: {"applied":[0],"document":{"a":null,"list":[true,1,false,0],"quote":{"$delete":true}}}

Output: {"applied":[0,1],"document":[]}
