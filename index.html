How the score works +

Deadline 3.5 discounts correctness by output-token usage. The 24 scored tasks total 1,050 points. Undiscounted correctness remains visible; missing usage is marked unmetered.

What the tasks measure +

27 public Python, JavaScript, and SQLite SQL tasks, using standard libraries. Most require reverse-engineering hidden behavior from observations; two are bug hunts across generated projects.

One blind attempt per task, per sample. This benchmark does not measure dependency wrangling or long agentic projects. Task 24 remains available but unscored because its prompt omits required final-state labels.

Results you can inspect +

Official and community submissions retain their provenance, with API and agent runs ranked separately. Entries from different suite hashes never share a board.

Open a model's post-mortem for the original commentary, task verdicts and contributions, full-pass points, sample counts, and timing assumptions. Current saved generations have one attempt per task; a regrade does not add an independent sample.

Version and measurement notes +
VERSIONS — Select v3.5 or v3.4 above the leaderboard. Each version keeps its own scores, task weights and grading rules. Version 3.5 regrades the same saved answers with expanded private coverage and q4 partial credit. Its headline includes output-token discounts; correctness remains alongside it. Tasks 19 and 22 are unscored because the public observations do not determine their hidden rounding rule and thresholds. Task 24 omits required state labels. Version 3.4 preserves 26 scored tasks, its q2 partial-credit rule and correctness headline. Only task 24 is unscored there. These are different scoring versions; their headline numbers are not directly comparable. The 3.5 change does not establish harder tasks or resolve correctness saturation. The mutation screen was reviewed against the full public contracts; it is a limited screen, not an exhaustive uniqueness proof. OFFICIAL identifies maintainer-run generations; existing entries have one attempt unless stated otherwise. A regrade reuses the same answer and does not add an independent sample. New certified runs require three attempts. Any displayed spread is repeat standard deviation, not a confidence interval. COMMUNITY answers are privately graded; model identity, effort settings and usage remain client reported. MEASUREMENTS — Measured Token DL requires complete token measurements. Reconstructed estimates are marked ≈, with assumptions in the post-mortem. Answer-file timestamps do not establish inference latency. TIME-DL uses archived answer intervals as a descriptive estimate; its timing coverage and assumptions are available in each expanded row. Version 3.5 ranks metered results by the token-discounted headline; unmetered results retain correctness without a headline rank. Version 3.4 ranks by correctness. Local regrades awaiting isolation remain private. See methodology and limitations. SCOPE — Deadline measures exact Python 3, JavaScript (Node), and SQLite SQL with standard libraries only, across 27 machine-generated tasks — most reverse-engineered from the observed behavior of hidden systems — in one blind attempt against token deadlines. Two tasks are whole-project bug hunts across dozens of generated files.
