How the score works +

Correctness is out of 100, using the published task points. The 26 scored tasks total 1,205 points. Semantic areas are balanced within each function, then across functions; SQL balances empty and nonempty results.

Completed answers earn q² − 0.15(1 − q)² credit, where q is the balanced matched fraction. Every case must pass for full credit. Invalid execution receives −15%; explicit skips earn zero; unresolved blank replies remain incomplete.

Token DL discounts positive credit when output exceeds the task's token budget. TIME-DL uses archived answer intervals and time budgets. These are separate from the headline correctness score.

What the tasks measure +

27 public Python, JavaScript, and SQLite SQL tasks, using standard libraries. Most require reverse-engineering hidden behavior from observations; two are bug hunts across generated projects.

One blind attempt per task, per sample. This benchmark does not measure dependency wrangling or long agentic projects. Task 24 remains available but unscored because its prompt omits required final-state labels.

Results you can inspect +

Official and community submissions retain their provenance, with API and agent runs ranked separately. Entries from different suite hashes never share a board.

Open a model's post-mortem for the original commentary, task verdicts and contributions, full-pass points, sample counts, and timing assumptions. Current saved generations have one attempt per task; a regrade does not add an independent sample.

Version and measurement notes +
VERSIONS — Each result identifies its grading version. The 26 scored tasks total 1,205 points. Scores from different versions are not directly comparable. Correctness is the headline; token efficiency is separate. Version 3.4 balances semantic areas and applies continuous signed credit, including negative penalties. Unresolved blank replies remain incomplete. OFFICIAL identifies maintainer-run generations; existing entries have one attempt unless stated otherwise. A regrade reuses the same answer and does not add an independent sample. New certified runs require three attempts. Any displayed spread is repeat standard deviation, not a confidence interval. COMMUNITY answers are privately graded; model identity, effort settings and usage remain client reported. MEASUREMENTS — Measured Token DL requires complete token measurements. Reconstructed estimates are marked ≈, with assumptions in the post-mortem. Answer-file timestamps do not establish inference latency. TIME-DL uses archived answer intervals as a descriptive estimate; its timing coverage and assumptions are available in each expanded row. Agent rows rank by correctness. Local regrades awaiting isolation remain private. See methodology and limitations. SCOPE — Deadline measures exact Python 3, JavaScript (Node), and SQLite SQL with standard libraries only, across 27 machine-generated tasks — most reverse-engineered from the observed behavior of hidden systems — in one blind attempt against token deadlines. Two tasks are whole-project bug hunts across dozens of generated files.
